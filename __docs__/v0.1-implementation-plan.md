# AI-DLC Usage Tracker — v0.1 Implementation Plan (final draft)

**Status:** Final draft for review (2026-10-20). It includes the review feedback, and step 0 (checking against real project data) is done; see §3b. Nothing is implemented yet.
**Build budget:** 1 developer-day (hard limit). The 1–2 week pilot runs afterwards and does **not** hold up the public release.
**Repo:** `sourcefuse/aidlc-usage-tracker`, public from day one. Licence: MIT. v0.1.0 is released as *experimental*.
**AI-DLC compatibility:**

- **Tested** on real audit records written by **AWS AI-DLC v2.10.0**, the version the pilot project runs.
- **Format checked** against the **v2.11.0** source. v2.11.1, the latest stable release (2026-10-20), leaves `aidlc-usage.ts` unchanged.
- The README documents both versions.

---

## 1. Goals

| # | Question | Answered by |
|---|---|---|
| G1 | Which team members have recorded AI-DLC usage, and which have not? | Activity per developer from the audit trail on `main`, compared against an optional `team.json` roster. |
| G2 | What did each implementation (intent) consume in tokens and estimated cost? | Lifetime usage per intent, plus per-developer contributions where the evidence supports attribution. |

Fewer, reliable numbers beat more numbers with false precision. When the evidence is incomplete, the report says so.

## 2. Architecture

AI-DLC already writes usage into **committed** audit files, so v0.1 is one read-only reporting script plus a GitHub Action. **`main` is the single authoritative source.**

```text
Developer: user story ─► runs AI-DLC locally ─► commits aidlc/ on a feature branch ─► PR ─► merged to main
                                                                                         │
Project AI-DLC repo: workflow (daily cron | manual | optional push to main, paths: aidlc/**)
   1. checkout main (fetch-depth: 0, needed for git authorship)
   2. node aidlc-usage-report.ts  ─►  usage-report.json + 3 CSVs
   3. actions/upload-artifact (retention 90 days). Nothing is committed.
```

**Not built:**

- Claude Code hooks, local collectors or publish queues;
- `repository_dispatch` or an ingest workflow;
- cross-branch scanning, remote-ref enumeration or worktrees;
- databases, dashboards or cost engines;
- identity services;
- SourceFuse-specific logic.

**Accepted consequence:** work that is unpushed or unmerged does not appear until its PR is merged.

## 3. Verified upstream facts the design depends on

Each of these was checked in the upstream source, not inferred.

| # | Fact | Evidence |
|---|---|---|
| F1 | `aidlc/` audit files are committed by design, as one file per clone: `audit/<hostname>-<clone-id>.md`. The local usage ledger (`aidlc/.aidlc-sessions/`) is gitignored. | `docs/guide/03-spaces-and-intents.md` ("What's committed"); `docs/guide/10-state-and-audit.md:240`; `harness/claude/dot-gitignore` |

A stage completed again (revisit, or a per-unit repeat in Construction) carries a total that **includes** the earlier completions. | `core/tools/aidlc-usage.ts` `stageUsageAuditFields` (~L1335) and `aggregateUsageAuditFields` (~L1305); the bucket is created once at ~L1010 with no reset path |
| F3 | **`WORKFLOW_COMPLETED` usage is that clone's whole-intent aggregate.** It covers all of that clone's sessions and includes usage outside any stage. **It does not include other developers' clones**, because each clone has its own gitignored ledger. | `workflowUsageAuditFields` (~L1345); F1 |
| F4 | Cost has three states: field absent means no usage; `Cost USD: null` means all usage was from unpriced models; a number means the priced portion. For mixed scopes, `By Model` shows unpriced models as `<model>=null`. | `aggregateUsageAuditFields` comment block (~L1293–1300) |
| F5 | `Cache Write` = `cacheCreate5m + cacheCreate1h`. | ~L1314 |
| F6 | Block format: split on `---`. Use the first `Timestamp` in each block, because older versions could write two. Read `Event` only from its own line. | `core/knowledge/aidlc-shared/audit-format.md` ("Emitter-Owned Fields"); L431 |
| F7 | Free-text fields (`Request`, `Details`, `User Input`, `Feedback`, `Person Reply`, …) can contain developer prompts. | `audit-format.md` ("Person Reply") |
| F8 | Only the Claude Code harness writes a usage ledger. Kiro, Codex and opencode produce audit activity with no usage. `AIDLC_DISABLE_USAGE_TRACKING=1` turns the ledger off. | `core/hooks/aidlc-fold-usage.ts:20-24, 66` |

### 3b. Confirmed on real project data (step 0, 2026-10-20)

**Sample:** one private project AI-DLC repo, read only.

- 11 intents and 16 audit files from 11 developers.
- 38 commits on `main`, 15 of them PR merge commits.
- AI-DLC v2.10.0.

The raw data stays outside this repo. Public fixtures will be sanitised derivatives.

| # | Finding | Effect on the design |
|---|---|---|
| F10 | **F2 confirmed.** One file shows the `code-generation` stage at $86.52 → $110.21 → $142.91 across three completions, and the `requirements-analysis` stage at $11.63 → $22.32. | Latest snapshot per stage, as planned. |
| F11 | **`WORKFLOW_COMPLETED` also repeats and is cumulative.** In one file an intent was completed three times: $172.92 → $226.00 → $283.54. | Use the **latest** `WORKFLOW_COMPLETED` per file. If a stage completes *after* it (the intent was reopened), take the larger of the workflow total and the stage total. No reconstruction. |
| F12 | **`<synthetic>=null` appears in `By Model` on nearly every usage event.** It has zero tokens and is absent from `Tokens By Model`. | An `=null` model counts as unpriced **only if it has tokens** in `Tokens By Model`. Otherwise `cost_has_unpriced` would be true everywhere. |
| F13 | **`intents.json` is missing 3 of the 11 intents on `main`.** The rows were probably lost when PR merge conflicts were resolved. | Find intents from directories (`intents/<dirName>/audit/`). The registry only adds `uuid` and `status`. Unregistered intents use `dirName` as their id, get their status from events, and are flagged `unregistered`. |
| F14 | **There are space-level audit files** (`intents/audit/*.md`) holding workspace init, health checks and guardrail events, with no intent. The developer who merges every PR appears **only** there. | Count them as developer **activity** (G1), never as intent usage. |
| F15 | **Merge commits are used.** With `--no-merges`, every audit file has exactly one author, and that author matches the file's hostname prefix. The merger is never credited. | §5 holds as designed. |
| F16 | A real git author email is wrapped in typographic quotes (`“name@domain”`) because of a misconfigured `user.email`. | Normalisation strips quotes. |
| F17 | Usage is blank, not zero, where a developer's audit file has completed stages but no usage fields at all. | Blank-not-zero rule, as planned. |
| F18 | **There are no worktree, Bolt or swarm events** (`AUDIT_MERGED` etc.). The 12 duplicate blocks found are all `HUMAN_TURN` or `SESSION_ENDED`, and none carry usage. | Drop the block-deduplication step: latest-snapshot accounting is already duplicate-safe. R3 stays a documented, unobserved risk. |
| F19 | There is a usage residual outside stages: a file's latest workflow total exceeds its stage total by $0.93–$39.28. | `unstaged` is a real, useful column. |

### Response to the review on aggregation (§4 of the review)

F3 means `WORKFLOW_COMPLETED` is authoritative **for the completing developer's clone only**, not for the whole intent. Using it as the intent total would undercount any intent with more than one contributor. The rule in §4 below gets the intent-level behaviour the review wanted (no stage-plus-workflow addition, no double-counting, discrepancies flagged) by working per audit file first and then summing across files. Summing across files is safe because each file comes from a separate, non-overlapping ledger (F1).

## 4. Accounting rules

The unit of accounting is the **audit file**: one clone, one ledger, normally one developer.

**Per audit file *s*, for intent *i*:**

1. **Stage total.** For each stage slug, take the **last** `STAGE_COMPLETED` usage by timestamp. Earlier completions of the same stage are superseded, because the values are cumulative (F2).
   - Use the latest valid snapshot. If it is **lower** than an earlier snapshot for the same stage, keep the latest anyway and flag `usage_decreased`. The local ledger was probably reset or migrated. There is no reconstruction logic, because the newer ledger may already include the historical consumption. This is a documented limitation.
   - Stage total = sum over stages of these values.
2. **File total.**
   - Take the **latest** `WORKFLOW_COMPLETED` with usage (F3, F11). It already includes all stages and usage outside stages. **Never add stage totals to it.**
   - File total = the **larger** of that workflow total and the stage total. The stage total is larger only when the intent was reopened after completing (F11). Taking the larger figure is a simple lower bound, not a reconstruction.
   - With no `WORKFLOW_COMPLETED`, the file total is the stage total.
   - The residual (workflow − stage total) is reported as `unstaged` (F19). A residual below zero, when not explained by a reopen, is flagged `discrepancy`.
3. **Cost.** Take cost from the same source as the chosen total.
   - Set `cost_has_unpriced` if `Cost USD` is `null`, or if a `By Model` entry is `=null` **and that model has tokens** in `Tokens By Model`. This ignores `<synthetic>` (F12).
   - Cost is never shown as 0 for unpriced usage.

**Per intent:** intent total = sum of its file totals. This is safe because the ledgers don't overlap.

**Lenient reporting:** report whatever usage the audit records provide.

- If no usage has been recorded yet, the token and cost cells stay **blank, not 0**.
- A single `usage_partial` indicator is `true` while the intent has no `WORKFLOW_COMPLETED`, or when a stage completed after the latest one (the intent was reopened).
- There are no further completeness rules or confidence model.

**Duplicates:** there is no deduplication step. Latest-snapshot accounting is unaffected by repeated blocks (F18).

**Intent discovery:** an intent is any `intents/<dirName>/` directory that has an `audit/` folder. `intents.json` adds `uuid` and `status` when it has a row; otherwise the intent is flagged `unregistered` (F13). Space-level audit files (`intents/audit/*.md`) count toward developer activity only (F14).

**Lifecycle, per intent, computed once:**

- `started_at` = earliest `WORKFLOW_STARTED`;
- `completed_at` = latest `WORKFLOW_COMPLETED` (blank if absent);
- `elapsed_hours` = wall clock between the two, blank if either is missing.

Status comes from `intents.json` (`in-flight` | `complete` | `archived`). An unregistered intent gets `complete` if it has a `WORKFLOW_COMPLETED`, and `in-flight` otherwise. A trailing `WORKFLOW_PARKED`, with no later `WORKFLOW_UNPARKED` or stage event, overrides the status as `parked`.

## 5. Developer attribution

The source is `git log --no-merges --format='%ae%x09%an' -- <audit file>`, run on `main`.

- **`--no-merges`** skips merge-commit authors, who are the mergers (F9), while still reaching the original commits.
- **Squash merges** give the PR author, which is correct for the one-developer-per-PR workflow.
- **Bot authors** (`*[bot]`) are ignored.

| Distinct human authors of the audit file | `attribution` | The file's usage goes to |
|---|---|---|
| exactly 1 | `attributed` | that developer |
| 2 or more | `ambiguous` | the `(ambiguous)` bucket; the candidate authors are listed in the JSON |
| 0 | `unattributed` | the `(unattributed)` bucket |

**Identity normalisation:**

- Lower-case the email and strip surrounding quotes, including typographic quotes (F16).
- `<id>+<login>@users.noreply.github.com` and `<login>@users.noreply.github.com` both map to the GitHub login.
- A roster entry matches on `github` login or any of its `emails`.

**Known edge case, documented rather than solved:** if one developer's PR contains another developer's audit file and is squash-merged, the file is attributed to the PR author. Co-author trailers are not parsed in v0.1.

## 6. Reporting periods

| Metric type | Period |
|---|---|
| Activity (first and last activity, active days, sessions) | **Selected period**, `--since`, default 30 days, from event timestamps |
| Token and cost usage | **Lifetime**, per intent and per (intent, developer). Never split across periods in v0.1, because cumulative snapshots can't be allocated to a period accurately without per-stage delta logic. That logic is deferred. |

Usage columns are prefixed `lifetime_` so the two are never confused. Lifetime and period figures are not reconciled against each other.

## 7. Outputs

`usage-report.json` is the normalised source of truth, and the CSVs are views of it. JSON fields:

- `schema_version`, `generated_at`;
- `source` (repo, ref, commit SHA);
- `aidlc_tested_version`, `period`;
- `intents[]`, `audit_files[]` and `developers[]`.

**Free-text audit fields are never read into the output** (F7).

**`developer-usage.csv`** — one row per person: roster members plus observed authors.
`developer, github, roster_status (active | no_usage_recorded | unmatched), period_start, period_end, first_activity, last_activity, active_days, sessions, intents_participated_lifetime, intents_completed_lifetime, lifetime_input_tokens, lifetime_output_tokens, lifetime_cache_read_tokens, lifetime_cache_write_tokens, lifetime_est_cost_usd, cost_has_unpriced`

- **`no_usage_recorded`** means *no AI-DLC activity in the merged audit records on `main`*. It is not a definitive claim of non-use.
- **`sessions`** counts `SESSION_STARTED` and `SESSION_RESUMED` events. `SESSION_ENDED` is not used, because it is sometimes written twice (F18).
- **Activity** includes the space-level audit files (F14).

**`implementation-usage.csv`** — one row per intent.
`space, intent_id, slug (dirName if unregistered), status, contributors, started_at, completed_at, elapsed_hours, stages_completed, input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, est_cost_usd, cost_has_unpriced, usage_partial, unstaged_tokens, flags`

**`implementation-developer-usage.csv`** — one row per (intent, developer), plus `(ambiguous)` and `(unattributed)` rows when present.
The token and cost columns are the same as above, plus `attribution`. **The rows for each intent sum exactly to the intent's row.** Tests check this.

Cost columns are labelled *estimated, list price*. Missing values are blank, never 0.

## 8. Code shape (so future integrations need no rewrite)

```text
src/aidlc-usage-report.ts   # parse → account → attribute → JSON; CSV writer; CLI entry. Zero runtime dependencies.
```

- **Pure functions** handle parsing, accounting and aggregation. Git access sits in one small function, so the core runs locally and is independent of GitHub Actions.
- **CLI:**

  ```text
  node src/aidlc-usage-report.ts --repo <path> [--since 30d] [--roster .aidlc-usage/team.json] [--out <dir>]
  ```
  It reads the checked-out tree and history at `HEAD`. The Action checks out `main`.

- **Runtime:** erasable-syntax TypeScript. It runs on Node ≥ 22.18 (native type stripping, no build step) and on Bun, upstream's runtime, so it can later move into an AI-DLC plugin `tools/` folder.
- **Integrations** (dashboards, OpenTelemetry, `sf-ai-dlc`) consume `usage-report.json`. None are built in v0.1.

## 10. Acceptance tests

Implemented as tests that build a temporary git repo from fixtures, with real `git` commits under different authors, plus one end-to-end run in Actions.

| # | Scenario | Pass condition |
|---|---|---|
| A | One developer completes an intent; the PR is squash-merged by **someone else** | Usage is attributed to the PR author, not the merger. `usage_partial=false`. |
| B | Two developers with separate audit files on one intent | Both are listed as contributors. The intent total = the sum of the two file totals. Per-developer rows reconcile. Nothing is split without evidence. |
| C | A stage is completed, revisited and completed again; the workflow is completed, reopened and completed again (F10, F11) | Only the latest cumulative values count, with no double-counting. A merge-commit variant also checks that `--no-merges` keeps the original author. |
| C2 | An intent is missing from `intents.json`; a developer has only space-level audit files (F13, F14) | The intent still appears, flagged `unregistered`. The developer appears as active, with no usage. |
| D | An audit file exists only on an unmerged branch | It is excluded. After merging to `main`, it appears in the next run. |
| E | An intent has activity but no completed stage | Usage cells blank (not 0), `usage_partial=true`, and activity still shown. |
| F | A roster member has no audit activity | The member appears as `no_usage_recorded`. |
| + | `Cost USD: null`; mixed `By Model` with `=null`; a stage snapshot lower than an earlier one; `WORKFLOW_COMPLETED` < stage total | `cost_has_unpriced` is set. For the lower snapshot, the latest value is used and `usage_decreased` is flagged. The `discrepancy` flag is set. No cost is shown as 0. |
| + | Privacy | No free-text field value appears in any output. |
| E2E | The workflow runs on a real project AI-DLC repo | CSV and JSON artifacts are downloadable from the run, and `git status` stays clean (nothing committed). |

## 12. Known limitations (README)

1. **Only merged work counts.** Usage appears after the PR merges to `main`.
2. **Partial usage on shared intents.** A contributor who didn't run `WORKFLOW_COMPLETED` contributes only their completed-stage snapshots. Their usage outside stages and on stages in progress is not visible.
3. **Ledger resets are not reconstructed.** If a developer's local ledger is reset or migrated, the latest snapshot is used as reported, and the drop is flagged as `usage_decreased`.
4. **Identity is the git author.** It is self-declared. A squash merge credits the PR author, and co-author trailers are ignored.
5. **No usage figures from non-Claude harnesses.** The usage cells are blank.
6. **No period-specific cost.** Usage is lifetime only.
7. **Plain Claude Code use outside AI-DLC is not detected.**
8. **Cost is an AI-DLC list-price estimate**, not a bill.
